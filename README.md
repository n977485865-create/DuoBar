# DuoBar

把电池、Wi-Fi 和四项状态放进一个圆形菜单栏图标。原生 AppKit、本地运行，没有 Dock 图标、账号或额外依赖。

**[下载安装包](https://github.com/n977485865-create/DuoBar/releases)** · **[完整安装说明](docs/安装说明.txt)**

本分支为专注过滤条件验证版，尚未发布。2026-09-15 在 macOS 27.0 实测发现：系统可以发现 DuoBar，但拒绝与临时签名的应用建立 App Intents 连接，配置无法添加。需要开发者完成有效签名后继续验收；当前版本不能提供专注联动。

## 安装

下载 Release 中的 `DuoBar-1.0.0-universal.dmg`，打开后把 **DuoBar.app 拖进 Applications**，再从“应用程序”中启动。也可以下载 ZIP，解压后把应用移到“应用程序”。

安装包包含 Apple Silicon 和 Intel 两种架构，要求 macOS 13 或更新版本。Apple Silicon 已实机验证，Intel 已完成编译与架构检查，尚未在 Intel 真机验收。

当前版本未使用 Developer ID 签名，也未经过 Apple 公证。首次打开可能被 macOS 拦截。确认文件来自本项目后，先尝试打开，再进入 **系统设置 → 隐私与安全性 → 仍要打开**，按系统提示确认。无需关闭整机安全机制或运行终端命令。受企业管理的 Mac 可能无法自行允许。

## 第一次使用

第一次启动会显示设置。图标和动画已经包含在应用中，但系统权限和菜单栏位置需要在每台 Mac 上分别设置。

1. **位置**：按住 ⌘ 拖动 DuoBar 到控制中心左侧。macOS 会记住你的位置；应用不强行重排其他图标。公开 API 没有按另一个应用的图标进行相对定位的选项，因此不能保证首次安装自动出现在所有 Mac 的同一位置。
2. **原生图标**：点击“关闭对应状态栏”，在系统设置中选择是否隐藏原生 Wi-Fi、电池等图标。
3. **登录启动**：需要时勾选“登录时自动启动”。
4. **Wi-Fi 名称**：需要时允许定位权限。没有权限仍显示连接与信号，应用不请求地理坐标。
5. **专注圆点**：当前测试版提示“专注联动暂不可用”，需要开发者完成签名。完成签名和实机验收后，预期使用方式为：进入 **系统设置 → 专注模式 → 勿扰模式 → 添加过滤条件**，选择 **DuoBar**，把“专注圆点”设为 **点亮**后添加。工作、睡眠等模式各自添加一次；没有添加的模式不联动。下载者不需要 Apple 开发者账号。

单击菜单栏图标查看详情，按 Esc 或点击外部收起。没有悬停展开。

状态行右侧的箭头表示可进入设置。点击带箭头的整行会收起菜单，直接打开对应系统页面：Wi-Fi、电池、蓝牙、声音或专注模式。有线网络状态会进入网络设置。VPN 行显示连接状态，不提供跳转。

## 图标与圆点

- 电池圆弧外径 26 pt、线宽 2.47 pt，底部圆点直径 3.12 pt。电量降低时从右侧开始消退，左端固定。
- 中间的 Wi-Fi 图形整体放大 1.15 倍，保持居中；信号用“信号很好 / 信号一般 / 信号较弱”表达。
- 底部圆点从左到右默认为 **VPN、耳机、静音、专注**。四个圆点等大；开启时点亮，未开启或未知时以 50% 不透明度显示灰色。
- 设置里可调整圆点顺序、单独隐藏或全部隐藏，立即生效并在重启后保留。隐藏的是圆点，菜单仍可查看状态详情。
- Wi-Fi 连接、网络名称、信号档位或四个状态开关变化时，Wi-Fi 保持正向并淡入切换；电量圆弧和圆点作为完整外圈同步转动，保持相对间距，轻微回弹后归位，约 1.43 秒结束。旋转由 Core Animation 合成；连续更新不会从头重播，结束后保持静止。点击打开菜单也会播放一次相同的旋转。
- 电量变化平滑补间；首次启动和同一信号档位内的小波动不触发旋转。系统开启“减少动态效果”时直接显示新状态。
- 省电模式开启时圆环显示系统黄色，优先于接电绿色；关闭省电模式后根据供电状态恢复颜色。
- 接通电源时圆环平滑变绿并轻扫一次，约 1.05 秒结束，未开启省电模式时，连接期间保持绿色（包括充电暂停或已充满）。断开后平滑恢复普通颜色。持续充电不会不断播放动画。

不同电脑的电量、连接设备、VPN 和专注状态不同，亮点数量与实际数值也会不同。台式 Mac 没有内置电池时显示外接电源，不会编造电量。

## 本地处理与限制

没有账号、云同步、服务器、遥测或第三方运行库。只保存圆点显示设置等本机偏好。

| 状态 | 读取方式与边界 |
| --- | --- |
| 电池 | IOKit 电源信息；ProcessInfo 省电模式状态 |
| Wi-Fi | CoreWLAN；SSID 可能被系统隐去 |
| VPN | 系统连接服务、系统代理及可确认的广域 TUN 路由；适配 Mihomo 分段路由。普通 utun 本身不会点亮。它表示配置或路由状态，不验证互联网可达性或加密状况 |
| 耳机 | CoreAudio 已连接并提供输出通道的耳机；普通蓝牙键鼠不会点亮 |
| 静音 | 默认输出的静音标记或零音量；不录制、读取或播放音频 |
| 专注 | App Intents 原生专注过滤条件；只跟随用户已绑定的模式，不读取受保护的系统数据库 |

系统事件驱动刷新，另以 30 秒补查；菜单打开时补查间隔为 3 秒。专注状态单独每 2 秒补查一次，睡眠时停止补查。

## 开发与构建

构建需要 macOS 和完整 Xcode，用于生成系统识别专注过滤条件所需的 App Intents 元数据。仅安装 Command Line Tools 可以运行测试，不能构建可连接的过滤条件。使用已构建的安装包不需要 Xcode。

```sh
./scripts/test.sh
./scripts/build.sh
./scripts/package.sh --skip-build
```

- 应用：`build/DuoBar.app`
- 安装磁盘：`dist/DuoBar-1.0.0-universal.dmg`
- 压缩包：`dist/DuoBar-1.0.0-universal.zip`

每次构建从空应用目录开始。打包前检查主程序、应用信息、图标、签名及原生 App Intents 元数据，并核验两种架构和系统库依赖。ZIP 不携带 AppleDouble 附加文件；测试、诊断脚本和本机偏好不会进入安装包。

状态检查覆盖组合、未知状态、显示偏好保存、Wi-Fi 文案、VPN 路由和动画触发。专注过滤条件测试直接执行开启和关闭回调。AppKit 检查验证电量方向、圆点大小、真实图层的状态变化、点击动画、连续更新不中断旋转和充电过渡。GitHub Actions 自动运行检查并构建两种架构。

此前实机验收为 Apple Silicon / macOS 26.6.2，包含菜单交互、圆点设置与重启保留、状态读取、系统设置跳转及登录项注册/取消。当前专注过滤条件已在 macOS 27.0 的系统列表中显示，但添加配置被签名身份检查阻止，真实开关切换未完成。具体证据见 [专注联动验证记录](docs/专注联动验证记录.md)。实际注销登录、睡眠唤醒、Intel 和其他 macOS 版本尚未验收。

## macOS 菜单栏开关已开但图标不显示

本机在 macOS 26.6.2 出现过 DuoBar 开关开启、图标仍被控制中心阻止的情况。实际验证发现关闭 ChatGPT 的菜单栏开关会隐藏 DuoBar，重新开启后恢复。DuoBar 的程序和安装包不依赖 ChatGPT；本机的系统关联记录也不包含在安装包中。

2026-09-15 已在本机修复并验收：备份系统菜单栏配置后，仅移除了 ChatGPT 条目对 DuoBar 的错误引用，刷新菜单栏并从 Finder 启动。随后关闭 ChatGPT 的菜单栏开关，系统窗口合成器确认 DuoBar 的菜单栏窗口仍在屏幕内，用户也确认图标正常显示且能打开状态面板。本机修复工具不包含在应用和安装包中。

macOS 26 的其他菜单栏应用也报告过由终端或 AI 工具启动后被错误归到启动方的菜单栏开关下，见 [CodexBar 的复现与处理记录](https://github.com/steipete/CodexBar/issues/1945)。开发测试和正常使用应从 Finder 的“应用程序”文件夹启动。重新打包不会清除已经产生的系统关联记录；本次修复与新安装环境的兼容性验收需分别判断。
