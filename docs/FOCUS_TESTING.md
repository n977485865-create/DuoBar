# 专注共享状态验证

DuoBar 使用 `INFocusStatusCenter` 查询系统向此应用共享的通知静音状态。它不能证明系统所有专注模式均已关闭，也不能读取模式名称。此改动修正状态含义和诊断，并保留现有轮询。

## 自动化检查

运行 `./scripts/test.sh`。Focus 专项测试注入可控数据源，验证授权、可选状态、状态与诊断快照一致性。测试不请求系统授权或切换专注模式。

2026-09-17 在 macOS 27.0（26A428）上，74 项状态检查、54 项 Focus 专项检查和两组 AppKit 检查通过；`scripts/build.sh` 的 arm64 / x86_64 编译、签名和包校验通过。独立 Bundle ID 的界面测试副本已验证未授权提示、诊断窗口打开和关闭、GUI 上下文与 null 值显示，以及布局无截断。CLI 的 `commandLine` 上下文也已核对。上述结果不包含授权后的真实专注开关切换。

## 实机检查

从 Finder 启动准备验证的应用包，记录系统版本、应用版本及构建号。使用设置中的“专注诊断”获得当前 GUI 进程的读数；不要把直接运行可执行文件的 CLI 诊断当成这个进程的权限。

| 场景 | 应检查的行为 |
| --- | --- |
| 尚未决定 Focus 授权 | 显示“尚未授权”；只有点击授权按钮才请求权限 |
| 拒绝授权 | 显示“授权被拒绝”，可以进入设置；不反复弹出权限请求 |
| 系统限制访问 | 显示“访问受限制”；不会承诺再次授权可以解除限制 |
| 授权后返回 nil | 显示“共享状态不可用”；保留 null，不当作关闭或拒绝授权 |
| 授权后返回 false | 显示“未报告静音”，圆点不亮；不宣称系统专注模式关闭 |
| 授权后返回 true | 显示“已报告静音”，圆点点亮 |
| 在专注设置中允许此应用通知 | 记录共享值，允许它与系统总开关不同 |
| 开关专注状态共享 | 记录原始授权与共享值，核对提示是否符合实际返回值 |
| 开启→关闭→再次开启一个专注模式 | 记录模式、允许通知名单、每步 GUI 读数与更新时间 |
| 应用重启、睡眠唤醒 | 验证轮询恢复，并重新读取诊断 |

“专注诊断”应打开一个可选择、可复制的报告窗口。查看报告不会请求通知权限、发送通知或自动复制到剪贴板。报告内容应与本次 Focus 采样一致；关闭后仍能正常刷新状态。

## 仍待验证的配置

Apple 的[通信通知与 Focus 示例](https://developer.apple.com/documentation/UserNotifications/handling-communication-notifications-and-focus-status-updates)列出了通知授权、Focus 授权和 Communication Notifications 能力。该示例项目主要面向 iOS / Mac Catalyst，其配置对原生 macOS 的适用性需要另行实测。

本次改动仅查询这些条件，未增加通知授权请求、通信通知 entitlement 或虚构消息/通话 intents；不能据此宣称底层读取问题已修复。诊断中的 entitlement 若返回 `unavailable`，表示检查失败，不等同于确定缺失。
