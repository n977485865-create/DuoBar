# 专注联动验证记录

2026-09-15，Apple Silicon，macOS 27.0（26A428）。结果：**未完成，受开发者签名身份阻塞**。

## 原有读取接口

勿扰模式开启、共享专注状态开启、没有通知例外，用户也已允许 DuoBar 读取专注状态和通知。`INFocusStatusCenter` 仍返回 false。DuoBar 进程的系统日志给出：

```text
DNDErrorDomain Code=1004
App is missing Communication Notifications entitlement.
```

向临时签名的验证副本加入该声明后，系统拒绝启动，诊断入口退出码为 137：

```text
AppleMobileFileIntegrityError Code=-424
The file is adhoc signed but contains restricted entitlements
```

此试验声明已移除，没有加入正式安装包。

## 原生专注过滤条件

改用 `SetFocusFilterIntent`，不增加通知权限、私人数据库读取、辅助进程或应用群组。完整 Xcode 生成原生元数据；本机测试、GitHub Actions 测试、双架构构建和签名完整性检查通过。应用从 Finder 启动。

退出并重新启动系统设置后，DuoBar 出现在“勿扰模式 → 添加过滤条件”列表。可以选择“专注圆点 → 点亮”，但“添加”按钮不可用。系统随后明确拒绝连接：

```text
Unable to get teamId from com.corale.duobar
Rejecting invalid client due to requiresValidatedBundle
LNConnectionErrorDomain Code=1200 "AppleEvents communication failed."
```

因此，“编译成功”“能在列表看到”“直接调用 perform() 测试成功”均不代表真实专注联动通过。配置已取消，未改动原有勿扰开关、定时或通知例外。

## 当前边界与后续

- 验证版在缺少开发者签名身份时显示专注联动不可用，停止请求接口，避免把默认空值当成“未开启”。
- 已完成的原生过滤条件代码保留在 `codex/focus-filter` 分支，未替换正式 Release。
- 需要有效的开发者签名后，继续检查添加过滤条件、实际开启和关闭、运行中切换、退出后重新打开及睡眠唤醒。
- 最终下载者不需要开发者账号。这里缺少的是发行方对应用的签名；当前包不能宣称已支持专注联动。
